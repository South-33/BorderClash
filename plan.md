# BorderClash research harness plan

## Outcome and scope

Maintain a reliable public record of the Thailand–Cambodia border situation for ordinary readers today and for researchers decades from now. A future agent should be able to reconstruct distinct developments and trace important claims to their sources from Git and the private evidence archive. A well-researched cycle with no material changes is a successful cycle.

One Antigravity agent maintains the canonical research record. It moves freely among curation, timeline work, and synthesis. Every real cycle runs on South with Gemini Flash Medium (`gemini-3.8-flash-medium`), including manual and nonpublishing runs. Development and fake-agent tests can run on any machine. While South is unavailable, trusted harness code may prepare bounded audit packets for a tool-denied Flash Medium laptop reviewer; those reviews can advance source analysis but do not satisfy real-cycle or South acceptance. The harness owns scheduling, isolation, validation, capture mechanics, Git integration, and publication. Follow [AGENTS.md](AGENTS.md) for editorial rules. Keep the existing dashboard and its public data contract compatible, including layout, text, controls, timer behavior, feeds, and the Highlights cutoff. Any UI change requires the operator's explicit approval. South's `BorderClashResearch` task stays disabled until the operator explicitly approves enabling it.

Implementation agents may refactor, rewrite, or replace the harness, schema, and repository layout. Choose the simplest design that passes the acceptance checks. Keep stable record IDs, the single permanent `main` workflow, and recoverable work. Prove the harness and data shape on fixtures and a nonpublishing run before migrating or auditing the live record.
